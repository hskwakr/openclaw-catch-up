# ZeroClaw + Codex OAuth + Discord セットアップ手順

*作成日: 2026-03-24*

## 目的

実機セットアップの前に「何をどの順でやるか」を整理する。過去ノート（07〜10）で決まった構成（ZeroClaw + Codex OAuth + Discord、Homebrew管理、Docker不使用）を前提とする。

## 全体の流れ

```
1. ZeroClawインストール（Homebrew）
2. Codex OAuth認証
3. config.toml の初期設定
4. Discord Bot 作成・設定
5. 動作確認
```

各ステップの所要時間目安: 合計30〜60分（Discord Developer Portalの操作に慣れているかで変動）。

---

## Step 1: ZeroClaw インストール

### コマンド

```bash
brew install zeroclaw
zeroclaw --version  # インストール確認
```

- Homebrew core formulaeに収録済み。tap追加は不要（ノート10）
- バイナリサイズ: 約8.8MB、メモリフットプリント: 約3.9MB
- 最新版は v0.6.1（2026年3月時点）

### 初回セットアップ

```bash
zeroclaw onboard --interactive
```

対話形式でconfig.tomlの雛形を生成してくれる。ただし後で手動編集するので、デフォルト値で進めてよい。

### 注意: Cargoビルドの場合

Homebrew以外でインストールする場合、Rust MSRV 1.87が必要。2026年3月時点のstable Rust（1.85〜1.86）では`cargo install`が失敗する。Homebrewなら問題なし。

## Step 2: Codex OAuth 認証

### 前提

- ChatGPT Plusサブスク（$20/月）が有効であること
- 「Sign in with ChatGPT」認証でAPIキー不要（ノート07）

### コマンド

```bash
zeroclaw auth login --provider openai-codex --device-code
```

### フロー

1. コマンド実行 → デバイスコードと認証URLが表示される
2. ブラウザで認証URLを開く
3. デバイスコードを入力
4. OpenAI/ChatGPTアカウントでログイン → 権限を付与
5. CLI側で認証完了が表示される

認証情報は `~/.zeroclaw/state/auth_profiles.json` に暗号化保存される。

### 認証確認

```bash
zeroclaw auth status
```

トークンの有効期限とプロバイダー情報が表示される。

### 利用可能モデル（要実機確認）

| モデル | アクセス名 | 備考 |
|--------|-----------|------|
| gpt-5.4 | `openai-codex/gpt-5.4` | メイン。Plus/Proで利用可 |
| gpt-5.4-mini | `openai-codex/gpt-5.4-mini` | 軽量タスク向け（要確認） |
| gpt-5.3-codex-spark | `openai-codex/gpt-5.3-codex-spark` | **Proサブスク（$200/月）限定**。研究プレビュー段階 |

⚠️ 実際にどのモデルが使えるかはOAuth認証後に確認する。ノート07の「まだ調べたいこと」の筆頭項目。

## Step 3: config.toml 初期設定

### ファイルの場所

```
~/.zeroclaw/config.toml
```

`zeroclaw onboard --interactive` で雛形が生成済み。以下を手動で編集する。

### 最小構成（まず動かす用）

```toml
[provider]
name = "openai-codex"
default_model = "gpt-5.4"

[security]
sandbox = true

[gateway]
port = 8080
```

### model_routes（Phase 2: Codex OAuthの動作確認後に追加）

```toml
[[model_routes]]
hint = "reasoning"
provider = "openai-codex"
model = "gpt-5.4"
priority = 100

[[model_routes]]
hint = "fast"
provider = "openai-codex"
model = "gpt-5.4-mini"
priority = 50
```

### query_classification（Phase 3: model_routesの動作確認後に追加）

```toml
[query_classification]
enabled = true

[[query_classification.rules]]
hint = "reasoning"
keywords = ["explain", "analyze", "why", "think through"]
min_length = 200
priority = 10

[[query_classification.rules]]
hint = "fast"
keywords = ["hi", "hello", "thanks", "quick"]
max_length = 50
priority = 5
```

⚠️ query_classificationのDiscordチャネル経由での動作はIssue #2537（修正済み）に関連。最新版なら問題ないはずだが要確認。

### config.toml はホットリロード対応

変更を保存すると即反映される。デーモン再起動は不要（ノート10）。

## Step 4: Discord Bot 作成・設定

### 4-1. Discord Developer Portal

1. https://discord.com/developers/applications にアクセス
2. 「New Application」→ 名前を付けて「Create」
3. 「Bot」セクション → 「Add Bot」

### 4-2. Privileged Gateway Intents（最重要）

Bot設定画面で以下を**必ず**有効にする:

- ✅ **Message Content Intent** — 有効にしないと接続→即切断のclose code `4014`（Disallowed Intent）エラーで再接続が無限ループする（セットアップ時の最頻出問題）。※ノート09では「Invalid Session (op 9)」と記載しているが、Discord公式ドキュメントによるとop 9はセッションロールオーバー時のエラーで、Intent未設定の場合は4014が正確
- ✅ **Server Members Intent** — メンバー検索とallowlistマッチングに必要（推奨）

### 4-3. Bot Token の取得

Bot設定画面で「Reset Token」→ トークンをコピー。このトークンは一度しか表示されないので安全な場所に保管する。

### 4-4. Botの招待

OAuth2 > URL Generator で:
- Scopes: `bot`
- Permissions: `Send Messages`, `Read Messages/View Channels`, `Read Message History`

生成されたURLでBotをサーバーに招待する。

### 4-5. config.toml に Discord設定を追加

```toml
[channels_config.discord]
bot_token = "YOUR_DISCORD_BOT_TOKEN_HERE"
guild_id = "サーバーID"
allowed_users = ["自分のDiscordユーザーID"]
mention_only = true
```

| 設定 | 説明 | 注意 |
|------|------|------|
| `bot_token` | Step 4-3で取得したトークン | 平文保存される。ファイルのパーミッションに注意 |
| `guild_id` | 対象サーバーのID（省略可） | 特定サーバーに限定する場合に設定 |
| `allowed_users` | 許可するユーザーIDのリスト | **空リスト = 全拒否**（deny-by-default） |
| `mention_only` | true = @メンションのみ応答 | falseだと全メッセージに応答 |

⚠️ `allowed_users` が空だと誰にも応答しない。自分のユーザーIDを必ず入れる。`["*"]`で全ユーザー許可も可能だが、deny-by-defaultの方針（ノート08）には反する。

⚠️ `guild_id` と `mention_only` フィールドはドキュメントで明示的に確認できていない。実機セットアップ時にZeroClaw Wikiの設定リファレンスで要確認。

### DiscordユーザーIDの確認方法

Discordの設定 > 詳細設定 > 開発者モードをON → 自分のプロフィールを右クリック → 「IDをコピー」

## Step 5: 動作確認

### 5-1. 基本ヘルスチェック

```bash
zeroclaw status          # 全体の状態
zeroclaw doctor          # 診断（依存関係・設定の問題を検出）
zeroclaw auth status     # Codex OAuth認証の状態
zeroclaw channel doctor  # Discordチャネルの接続状態
```

### 5-2. エージェント単体テスト（Discord抜き）

```bash
zeroclaw agent -m "What is 2+2?"
```

Codex OAuth経由でgpt-5.4に問い合わせが行く。応答が返ればOAuth認証は正常。

### 5-3. 特定プロバイダー指定テスト

```bash
zeroclaw agent --provider openai-codex --auth-profile openai-codex:default -m "Test message"
```

### 5-4. Discord経由テスト

```bash
zeroclaw daemon  # デーモン起動（チャネル・スケジューラー含む）
```

Discordサーバーで @Bot名 にメンションして応答を確認。

### 5-5. 確認すべきこと一覧

- [ ] `zeroclaw doctor` が全項目パス
- [ ] `zeroclaw auth status` でCodex OAuthが有効
- [ ] `zeroclaw agent -m "test"` で応答が返る
- [ ] 利用可能モデルの確認（gpt-5.4, gpt-5.4-mini, gpt-5.3-codex-spark）
- [ ] Discordで@メンションに応答する
- [ ] query_classificationが機能する（Discord経由）
- [ ] レート制限の体感確認（連続でメッセージを送ってみる）

### Phase 1: 最小構成で動かす
- ZeroClawインストール + Codex OAuth + 最小config.toml
- `zeroclaw agent -m "test"` で応答確認
- 利用可能モデルとレート制限の把握

- Discord Bot作成 + config.toml にDiscord設定追加
- `zeroclaw daemon` でDiscord経由の動作確認
- allowed_users、mention_onlyの挙動確認

### Phase 3: ルーティング設定
- model_routes追加 → ヒント指定での切り替え確認
- query_classification有効化 → Discord経由での自動ルーティング確認
- Issue #2537（チャネル起動時のmodel_routes反映）の影響がないか確認

### Phase 4: （将来）Claude API追加
- Claudeの使い方が決まったら
- `[agents.reviewer]` にClaude Sonnetを設定
- Anthropicコンソールで月間上限を設定

## トラブルシューティング

| 症状 | 原因（可能性） | 対処 |
|------|----------------|------|
| Discord接続→即切断ループ（close code 4014） | Message Content Intent未有効 | Developer PortalでIntentをON |
| Botが無反応 | `allowed_users` が空 | 自分のユーザーIDを追加 |
| `cargo install` が失敗 | Rust MSRV 1.87未満 | Homebrewを使う |
| OAuth認証エラー | ChatGPT Plusが無効 | サブスク状態を確認 |
| model_routesが効かない | Issue #2537の残存影響 | 最新版に更新、`zeroclaw doctor` で確認 |
