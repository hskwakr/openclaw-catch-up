# 軽量フォーク比較: OpenClaw vs NanoClaw vs ZeroClaw vs PicoClaw vs Nanobot

*2026-03-23 作成*

## なぜ比較するのか

OpenClaw本体はコードベースが巨大（43万行超）で、セキュリティ問題も複数報告されている。構成を決める前に、軽量フォークが自分の用途に合うかを検討する。比較軸はセキュリティ、コスト、機能、メンテナンス性。

## セキュリティ比較（最重要）

### OpenClaw

- **アプリケーションレベルの権限制御**: `tools.allow`/`tools.deny`、`skills.allowBundled` 等
- ホストユーザーと同じ権限で実行 → SSH鍵、クラウド認証情報、機密データにアクセス可能
- 既知のCVE: CVE-2026-25253（ワンクリックRCE, CVSS 8.8）、CVE-2026-26327（認証バイパス）
- ClawHubによるサプライチェーン攻撃リスク（ClawHavoc事件: 341の悪意あるスキル）
- Palo Alto Networksが「セキュリティ上の悪夢」と評価

### NanoClaw

- **OS レベルのコンテナ分離**: 各エージェントセッションが独立したLinuxコンテナ内で実行
- ファイルシステム分離、IPCネームスペース分離、プロセス空間分離
- Apple Container / Docker に対応
- プラグインマーケットプレイスがない → サプライチェーン攻撃の面がない
- コード量が少ない → 人間またはAIで約8分で全体を監査可能
- **制約**: Claude API専用（他のLLMをプロバイダーとして使えない）。ただし `/add-ollama-tool` スキルでOllamaをMCPツールとして接続可能（Claudeが判断してOllamaに委任する形。Claude APIコストは削減されない）

### ZeroClaw

- **Rustの型システムによるメモリ安全性**: バッファオーバーフロー、use-after-free、データ競合をコンパイル時に排除
- **deny-by-default のアクセス制御**: スキルは明示的に許可されたものだけアクセス可能
- ゲートウェイ認証に暗号学的認証を使用（パスワードだけではない）
- プラグインマーケットプレイスがない → サプライチェーン攻撃の面がない

### PicoClaw

- 機能が少ない → 攻撃面が小さい
- ただし公式READMEで「v1.0まで本番利用は避けるべき」と明記
- セキュリティ設計の詳細は公開情報が限定的

### Nanobot

- コードが読みやすく改造しやすい（4,000行のPython）
- 明示的なセキュリティ分離の仕組みは限定的
- 研究・学習目的が主

## コスト比較

### ソフトウェア自体のコスト

全てオープンソース・無料。実際のコストは **ホスティング + API利用料**。

### ホスティングコスト

| 構成 | 目安 |
|------|------|
| $5〜15/月のVPS | ZeroClaw, PicoClaw, Nanobot に十分 |
| NanoClaw（Docker必須） | VPS + Docker環境。$10〜20/月程度 |
| OpenClaw | Node.js + 各種依存。安全運用には専用マシンまたはVM推奨 |

### API トークンコスト（全フォーク共通の課題）

- 1回のやりとり: GPT-4o-miniで約$0.00045、GPT-4oで約$0.0075
- **月間目安**: 軽い利用で$6〜13/月、小チームで$25〜50/月、重い自動化で$100〜200+/月

### OpenClaw固有のトークンオーバーヘッド

OpenClawは**毎回のAPI呼び出しにシステムプロンプト（5,000〜10,000トークン）+ ツール定義 + スキルメタデータを再送**する。

- ツール定義だけで全24ツール分のスキーマが毎回送信される
- 会話が10ターン目になると、過去9ターン分の全コンテンツも再送
- 実際のトークン消費は理論値の5〜10倍になることがある

**軽量フォークの優位性**: ツール数もスキル数も少ないため、システムプロンプトのオーバーヘッドが構造的に小さい。NanoClawやZeroClawのほうがトークン効率が良い可能性が高い。

## 機能面のトレードオフ

### OpenClawでしかできないこと（現時点）

- 13,700+のサードパーティスキルへのアクセス
- 多数のLLMプロバイダーの切り替え
- 大規模コミュニティによるサポート・情報量
- エンタープライズ向け統合（Salesforce, Jira等）
- Heartbeat（プロアクティブ監視）

### NanoClaw の強み

- コンテナ分離という根本的なセキュリティモデル
- コード全体を読める規模感
- 「自分でフォークして改造する」という設計思想 → Claude Codeで改造可能
- **制約**: Claude API専用（OllamaはMCPツールとして利用可能だが、オーケストレーターはClaude固定）、プラグインエコシステムなし、エンタープライズ統合なし

### ZeroClaw の強み

- Rustによるメモリ安全性
- 超軽量（4MB RAM、10ms起動）
- deny-by-defaultのアクセス制御
- 30+チャネル対応
- **制約**: エコシステムが小さい、コミュニティもOpenClawより小さい

### PicoClaw の強み

- 超低スペックハードウェアで動作（$10のRISC-Vボード）
- IoT・組み込み向け
- **制約**: チャネル5つのみ、本番非推奨（v1.0未満）

### Nanobot の強み

- Pythonエコシステムとの親和性
- 学習・研究に最適
- **制約**: 機能が限定的、セキュリティ分離が弱い

## 構成選択に向けた論点

この比較から、構成を決めるための未回答の問いが見えてくる:

1. **Claude専用でいいか？** → YesならNanoClawが有力。他LLMも使いたいならZeroClawかOpenClaw
2. **どのチャネルを使うか？** → WhatsApp/Telegram/Slack程度ならどれでも対応。30+必要ならZeroClaw
3. **プラグインエコシステムは必要か？** → 必要ならOpenClaw一択。不要なら軽量フォークのほうがセキュア
4. **許容できるリスクレベルは？** → コンテナ分離が必須ならNanoClaw。deny-by-defaultならZeroClaw
5. **月間コスト予算は？** → VPS $5〜15 + API $6〜50 が実用的な範囲。OpenClawはトークンオーバーヘッドで割高になりうる
6. **自分で改造するか、コミュニティに頼るか？** → 改造派ならNanoClaw/Nanobot、コミュニティ依存ならOpenClaw
