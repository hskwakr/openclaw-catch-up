# スキル・ツール制御とセキュリティ

*2026-03-22 作成*

## 問題の構造

OpenClawのエージェントは、ユーザーの明示的な指示がなくても、以下の経路でスキルをインストール・有効化しうる:

```
1. バンドルスキル（53個）がデフォルトで全有効
2. ClawHubツール（ビルトイン）でエージェントが自発的にスキルを検索・提案
3. auto-updater スキルによるインストール済みスキルの自動更新
```

いずれも「ユーザーが明示的に選んだわけではないコードが実行可能になる」という点で共通のリスクを持つ。

---

## ClawHub = ビルトインツール

ClawHubは単なる外部レジストリではなく、**ビルトインツール（25〜26個、バージョンにより変動）の1つとしてエージェントに公開されている**。

ClawHubが有効な状態では:
- LLMが「このタスクにはXスキルが必要」と判断 → ClawHubを検索 → インストールを提案
- この流れがツールレベルで可能な設計になっている
- ユーザーの承認は挟まるが、LLMの提案に引きずられるリスクがある

**本質的な問題:** LLMが「必要」と判断する根拠はプロンプトとコンテキスト次第であり、プロンプトインジェクション等で操作されうる。

## 防御手段: 何ができて、何ができないか

### できること

#### 1. `tools.deny` でClawHubツールを無効化

```json
{
  "tools": {
    "deny": ["clawhub"]
  }
}
```

- `tools.deny` に入れたツールはLLMに送られるスキーマから除外される
- エージェントはClawHubの存在自体を知らなくなる
- **deny は allow より優先**（両方に入っていればdenyが勝つ）

#### 2. `tools.profile` + ホワイトリスト方式

プロファイルをベースに、必要なツールだけ追加する:

```json
{
  "tools": {
    "profile": "minimal",
    "allow": ["web_search", "web_fetch"],
    "deny": ["clawhub", "browser", "canvas", "nodes", "cron", "gateway"]
  }
}
```

**参考: サンドボックスのデフォルトポリシー**

| Allow | Deny |
|-------|------|
| bash, process, read, write, edit, sessions_* | browser, canvas, nodes, cron, discord, gateway |

#### 3. バンドルスキルのホワイトリスト

```json
{
  "skills": {
    "allowBundled": ["memory", "web-search"]
  }
}
```

使うバンドルスキルだけを明示的にリストする。

#### 4. 個別スキルの制御

```json
{
  "skills": {
    "entries": {
      "auto-updater": { "enabled": false },
      "some-skill": { "enabled": true }
    }
  }
}
```

- `enabled: false` — スキルを完全無効化
- スキルのフロントマターで `disable-model-invocation: true` — LLMからの自発的呼び出しを禁止（ユーザーのスラッシュコマンドからのみ実行可能）

### できないこと（未解決の問題）

| 問題 | 状態 | Issue |
|------|------|-------|
| `skills.allowBundled: []`（空配列）が全スキル許可になるバグ | 未修正 | [#21709](https://github.com/openclaw/openclaw/issues/21709) |
| Per-tool enable/disable（ツール単位の有効/無効切替） | Feature Request段階 | [#14812](https://github.com/openclaw/openclaw/issues/14812) |
| Per-agent allowlist（エージェント単位のスキル制限） | Feature Request段階 | [#15717](https://github.com/openclaw/openclaw/issues/15717) |
| `allowBundled` がサンドボックスsync時に無視される | 未修正 | [#10236](https://github.com/openclaw/openclaw/issues/10236) |

## 推奨セットアップ方針

セットアップ時に最初から適用すべき設定:

### 1. tools.deny でClawHubを封じる

```json
"tools": {
  "deny": ["clawhub"]
}
```

スキルの追加は手動CLIで行い、エージェントには検索・インストール権限を与えない。

### 2. tools.profile を minimal から始める

```json
"tools": {
  "profile": "minimal",
  "allow": ["必要なものだけ追加"]
}
```

### 3. バンドルスキルを明示的に絞る

```json
"skills": {
  "allowBundled": ["使うものだけリスト"]
}
```

**注意:** 空配列 `[]` はバグで全許可になるため、1つ以上を明示的にリストする必要がある。全ブロックしたい場合は、存在しないスキル名（例: `"__none__"`）を入れる回避策が考えられるが、動作は未検証。

### 4. auto-updater は入れない

スキルの更新は手動で行い、変更内容を確認してから適用する。

### 5. ファイルシステム権限を絞る

```bash
chmod 700 ~/.openclaw
chmod 600 ~/.openclaw/openclaw.json
chmod 700 ~/.openclaw/credentials
```

### 6. セキュリティ監査を実行

```bash
openclaw security audit --deep
```

## ビルトインツール（判明分）

情報源により25〜26個と幅がある（バージョンによる変動）。調査で特定できたツール名を、リスク別に整理（網羅的ではない可能性あり）:

**Layer 1 — コア（ほぼ必須）:**
read, write, list, search, exec, web_search, web_fetch, edit

**Layer 2 — 拡張（用途に応じて選択）:**
browser, canvas, image, memory, cron, gateway, message, nodes, clawhub, sessions_list, sessions_history, session_status, sessions_send, sessions_spawn, sessions_yield, subagents, llm_task, lobster

**特にリスクの高いツール:**
- `clawhub` — エージェントによるスキル検索・インストール
- `nodes` — リモートデバイス制御（カメラ、GPS）
- `gateway` — OpenClaw自身の再起動
- `cron` — 自動スケジュール実行
- `browser` — ブラウザ操作（クリック、フォーム入力）
