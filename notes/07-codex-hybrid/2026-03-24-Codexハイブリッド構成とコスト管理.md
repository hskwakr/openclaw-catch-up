# Codexハイブリッド構成とコスト管理

*2026-03-24 作成*

## このノートの位置づけ

Docker運用の調査で「セキュリティのためにDocker化したい」→「でもM4 16GBだとメモリがきつい」という壁にぶつかった。同時に、Claude APIの従量課金への不安から「ChatGPTサブスクでCodex CLIを主力に、Claudeは設計・レビューに限定」という方向性が浮上。ここではその実現可能性を調べる。

---

## 1. コスト構造の核心: サブスクとAPIは別世界

### 結論を先に

**Claude も OpenAI も、サブスクとAPIは別の課金体系。** フレームワーク（OpenClaw等）はAPIキーを要求するため、サブスク契約だけではフレームワークを動かせない——が、**回避策がある**。

| | ChatGPT サブスク | Claude サブスク |
|---|---|---|
| CLIツール利用 | ✅ Codex CLI含む | ✅ Claude Code含む |
| API直接利用 | ❌ 別課金 | ❌ 別課金 |
| OpenClaw等で利用 | ❌ APIキー必要 | ❌ APIキー必要 |
| **回避策** | ZeroClawがCodex OAuth対応 | コミュニティプロキシあり |

---

## 2. OpenAI Codex CLI の料金体系

### サブスク内包モデル

- **ChatGPT Plus ($20/月)**: Codex CLI利用可 + $5のプロモーションAPIクレジット
- **ChatGPT Pro ($200/月)**: Codex CLI利用可 + $50のAPIクレジット
- 「Sign in with ChatGPT」認証でCLIを動かす限り、**追加料金なし**
- APIキー経由の利用は別途従量課金（codex-mini: $1.50入力/$6.00出力 per 1Mトークン）

### 利用可能モデル

| モデル | 用途 | 備考 |
|--------|------|------|
| gpt-5.4 | コーディング・推論・一般タスク | 推奨デフォルト |
| gpt-5.4-mini | 軽量タスク向け | 高速・低コスト |
| gpt-5.3-codex-spark | 高速反復開発 | Proサブスク限定 |

### Claude Code との比較

| | Codex CLI | Claude Code |
|---|---|---|
| サブスクで利用 | ✅ ChatGPT Plus/Pro | ✅ Claude Pro/Max |
| 月額 | $20 / $200 | $20 / $100-200 |
| サブスクでAPI相当利用 | ❌（別課金） | ❌（別課金） |
| フレームワーク連携 | ZeroClawがOAuth対応 | プロキシで可能 |

## 3. フレームワーク連携: 鍵はZeroClaw

### OpenClaw + OpenAI

- ✅ OpenAI APIをバックエンドとして利用可能（gpt-5.4等）
- ❌ **ChatGPTサブスク認証では接続不可** — APIキー必須
- 設定: `openclaw onboard --openai-api-key` → 従量課金が発生

### ZeroClaw + Codex OAuth（重要な発見）

- ✅ **ZeroClawはCodex OAuthに対応している**
- `zeroclaw auth login --provider openai-codex --device-code` で認証
- ChatGPTサブスクのアカウントでログインすればAPIキー不要
- つまり**ChatGPT Plus ($20/月) でZeroClawを動かせる可能性がある**

⚠️ 要確認事項:
- Codex OAuthでのレート制限がどの程度か
- サブスク認証でのモデル選択肢（gpt-5.4が使えるか）
- Discord チャネル経由での利用時にOAuth認証が維持されるか

### Claude サブスクのプロキシ回避策

コミュニティが開発したプロキシツールで、Claude Max/ProサブスクのOAuthトークンをOpenAI互換APIフォーマットに変換可能:

- **CLIProxyAPI** — Claude Code OAuth → OpenAI互換API
- **claude-code-proxy** — 同上
- **claude-max-api-proxy-rs** — Rust実装（軽量）

⚠️ これらは非公式ツール。Anthropicの利用規約に抵触する可能性あり。アカウントBANのリスクは未知数。

## 6. Claudeの使いどころ

API従量課金が怖いという前提で、Claudeを使う場面を絞る:

### コスト効率の高い使い方

- **アーキテクチャ設計のレビュー**: 1回の長い会話で$0.50-2.00程度。頻度が低いので月額は抑えられる
- **コードレビュー**: PRの差分を渡して品質チェック。1回$0.10-0.50
- **セキュリティ監査**: 設定ファイルや新しいスキルの安全性チェック

### 避けるべき使い方（コスト爆発しやすい）

- 日常的なコーディングタスク（→ Codex/Ollamaで代替）
- 長い対話セッション（トークン再送で累積コスト増）
- 定期的な自動実行（Heartbeat等）

### 上限設定

Claude APIには使用量の上限を設定可能:
- Anthropic Consoleで月間予算上限を設定
- アラート設定で閾値超えを通知

## 8. ZeroClawからClaude Codeを呼び出す検討（追記 2026-03-24）

### 背景

Claude APIの従量課金を避けるため、「ZeroClawがClaude Code CLIをサブプロセスとして起動し、Claudeサブスク認証で設計・レビューを行う」アプローチを検討した。

### 技術的には可能

Claude Code CLIには非対話モード（`-p` / `--print` フラグ）があり、サブプロセスとして呼び出せる:

```bash
claude -p "このアーキテクチャをレビューしてください: ..."
```

- `--bare` フラグの存在は公式ドキュメントで確認できず（要実機確認）
- 認証はOAuthトークン（`claude auth login` で取得）
- コミュニティプロジェクト [steipete/claude-code-mcp](https://github.com/steipete/claude-code-mcp) がClaude CodeをMCPサーバーとしてラップする実装を提供

ZeroClawからの統合パターン:

| パターン | 方法 | 利点 | リスク |
|---------|------|------|-------|
| ShellTool | `claude -p "prompt"` | 最も簡単 | 出力がプレーンテキスト |
| MCPサーバー | claude-code-mcp経由 | 構造化された通信 | 設定が複雑 |
| Agent SDK | Claude Agent SDK経由 | 公式サポート | **APIキー必須**（サブスク不可） |

### ⚠️ 利用規約の壁（致命的な問題）

**2026年2月、Anthropicが明確化した方針:**

> OAuthトークンはClaude CodeとClaude.ai専用。他のプロダクトでの利用は利用規約違反。

具体的には:
- サブスクのOAuth認証を「自動化された、または人間以外の手段」で利用することは禁止
- **APIキー経由のみ**が自動化利用として公式に認められている
- OpenCodeなどのサードパーティツールはAnthropicの法的要請により2026年1月にClaude Pro/Maxサポートを削除済み
- CLIProxyAPI等のプロキシツールも同様のリスクを負う

**つまり: ZeroClawからClaude Codeをサブプロセスで呼ぶ構成は、技術的には動くが、利用規約違反でアカウントBANのリスクがある。**

### Claude Codeのレート制限（参考）

仮に使えたとしても、サブスクのレート制限は自動化に向いていない:

| プラン | 制限 | 自動化での実用性 |
|--------|------|-----------------|
| Pro ($20/月) | 5時間ウィンドウで10-45メッセージ | ✕ 15-30分の集中利用で上限到達 |
| Max 5x ($100/月) | 5時間ウィンドウで225+メッセージ | △ 軽い利用なら可能 |
| Max 20x ($200/月) | 5時間ウィンドウで900+メッセージ | ○ 実用的だが$200/月 |

### 結論: Claudeサブスクの自動利用は断念すべき

Anthropicは意図的にサブスク（対話用）とAPI（プログラマティック用）を分離している。これは価格裁定を防ぐための設計上の判断であり、見落としではない。

### 代替アプローチ

| 方法 | コスト | 規約 | 実用性 |
|------|--------|------|--------|
| Claude API（Sonnet）を設計レビューのみ | $5-15/月（利用頻度による） | ✅ 合法 | ○ |
| Claude API（Haiku）で軽いレビュー | $1-5/月 | ✅ 合法 | ○ |
| API月間上限をAnthropicコンソールで設定 | 上限次第 | ✅ 合法 | ○ |
| Claudeを使わずCodex + Ollamaだけ | $0追加 | ✅ 合法 | △（品質は劣る） |

**推奨**: Claude APIをSonnetで使い、Anthropicコンソールで月間上限を$15-20に設定する。設計・レビューの頻度を週1-2回に抑えれば十分収まる。

## 10. ZeroClawのオーケストレーション機能（追記 2026-03-24）

### マルチプロバイダー: 対応済み

ZeroClawは28+のプロバイダーに対応しており、**複数を同時に設定可能**。

### タスク振り分けの仕組み

3つのメカニズムがある:

**A. ヒントベースの手動ルーティング**

`[[model_routes]]` でヒント名とプロバイダー/モデルを紐づける:

```toml
[[model_routes]]
hint = "fast"
provider = "ollama"
model = "qwen2.5-coder:7b"

[[model_routes]]
hint = "reasoning"
provider = "openai"  # Codex OAuthの場合
model = "gpt-5.4"

[[model_routes]]
hint = "review"
provider = "anthropic"
model = "claude-sonnet-4-6"
```

ユーザーが `hint:fast` と指定すると対応するモデルにルーティングされる。

**B. 自動クエリ分類（設定で有効化）**

メッセージの内容に基づいて自動的にヒントを割り当てるルールを定義可能:

```toml
[query_classification]
enabled = true
rules = [
  { patterns = ["explain", "analyze", "why"], hint = "reasoning", min_length = 200, priority = 10 },
  { patterns = ["hi", "hello", "thanks"], hint = "fast", max_length = 50, priority = 5 }
]
```

**C. サブエージェント委任**

異なるモデルを持つサブエージェントを定義し、タスクを委任可能:

```toml
[agents.coder]
provider = "ollama"
model = "qwen2.5-coder:7b"
allowed_tools = ["file_write", "shell_exec"]

[agents.reviewer]
provider = "anthropic"
model = "claude-sonnet-4-6"
allowed_tools = ["file_read", "web_search"]
```

### ないもの

- ❌ **コストベースの自動最適化**: 手動でルール設定が必要
- ❌ **フォールバック時のモデル名再マッピング**: バグあり（Issue #1646）
- ❌ **チャネル起動時のmodel_routes反映**: バグあり（Issue #2537）

### Ollamaの位置づけについて

ZeroClawのオーケストレーションを踏まえると、Ollamaの使い方は2パターン:

1. **デフォルトプロバイダーとして**: 大半のタスクをローカルで処理し、複雑なタスクだけクラウドにフォールバック
2. **補助的なfast用プロバイダーとして**: Codex OAuthをメインに、簡単な応答だけOllamaに回す

ただし**Codex OAuthが定額で使い放題なら、Ollamaを入れる実用的メリットは限定的**。Ollamaが有用なのは:
- ネットワーク接続なしで使いたい場合
- プライバシー上、ローカル処理したいデータがある場合
- レスポンス速度を極限まで追求する場合（ネットワークラウンドトリップ排除）

→ **決定を急がず、まずCodex OAuthだけで始めて、必要を感じたら追加**が合理的。
