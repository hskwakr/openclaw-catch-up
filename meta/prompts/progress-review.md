# PROGRESS見直し プロンプト

## 用途

PROGRESS.mdが肥大化・陳腐化していないかを定期的にチェックするとき使う。
セッションの冒頭や、大きな調査トピックが完了したタイミングで実行するのが理想。

---

## プロンプト

```
PROGRESS.mdを見直してください。

PROGRESS.mdの役割は「再開のエントリーポイント」です。
「今どこにいて、次に何をするか」がすぐにわかることが最優先。

以下の観点でチェックし、必要があれば修正を提案してください:

1. **決まっていないこと → 決まったこと**
   - 方針がほぼ固まった項目はないか？
   - 「決まっていないこと」に残っているが、実質的に結論が出ているものを「決まっていること」に移す

2. **まだ気になっていること → 解決済み**
   - 調査やIssueの進展で解消された懸念はないか？
   - 解決済みのものは「調査済み（解決済み）」に移す

3. **セクション間の重複**
   - 「次にやること」と「まだ気になっていること」に同じ内容が重複していないか？
   - 重複がある場合、どちらに残すのが適切か判断する

4. **次にやることの優先順位**
   - 状況の変化で優先順位が変わっていないか？
   - 完了した項目が残っていないか？
   - 具体的なアクションとして実行可能か？（抽象的すぎないか）

5. **肥大化チェック**
   - 「調査で判明した重要事項」が長くなりすぎていないか？
   - 完了済みで今は参照不要な情報が本文に残っていないか？
   - 取り消し線（~~）付きの解決済み項目が溜まっていたら meta/progress/ に退避する

6. **ノート一覧の整合性**
   - 新しく作成したノートがリストに反映されているか？
   - リンク切れがないか？

修正したら最終更新日を更新してください。
```

---

## 使い方のコツ

- セッション冒頭で PROGRESS.md を読んだ直後に実行するのが自然な流れ
- ファクトチェックプロンプトと組み合わせると効果的（ファクトチェック → PROGRESS見直し）
- 大きな退避を行うときは meta/progress/YYYY-MM.md を事前に確認する
